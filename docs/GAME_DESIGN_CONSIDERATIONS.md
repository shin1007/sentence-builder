# このゲームを作る／育てる上で気にすべきこと

「ワードオーダー・ラッシュ」（英単語ならべかえPWA）のような、**子ども向け・語順パズル型・英語学習・PWA** ゲームを開発・改修する際に検討すべき論点のメモ。将来のセッションで参照する目的で残す。実装済みの箇所は該当ファイルを添え、未対応/要検討の箇所は理由とセットで書く。

## 1. ゲームデザイン・バランス

- **スコアリングの公平性**: `src/components/GameScreen.tsx` の `resolve()` は `timeBonus = timeLeft * 2` を加算しており、正確さより速さが得点を左右する。じっくり考える子が不利にならないか。
- **ライフ制のプレッシャー**: `START_LIVES = 3` で残機切れ即終了。学習アプリとしては失敗への不安を生みやすい。タイマー・ライフなしの「練習モード」の価値を検討。
- **出題プールの枯渇**: `src/data/questions.ts` の `pickQuestions()` は全問題をシャッフルして先頭N問を返すだけ。テンプレート×語彙（`questionGen.ts`, `vocab.ts`）のバリエーション数と重複排除ロジックを確認し、繰り返しプレイでの暗記ゲー化を防ぐ。
- **難易度カーブ**: レベル内の出題順が完全ランダムなため、難しい構文が1問目に来ることがある。段階的難易度にするかは意図次第。
- **タイムリミットの根拠**: `src/data/levels.ts` でレベルが上がるほど制限時間が短くなる（26秒→19秒）一方、文は長く複雑になる。対象年齢での実プレイテストが必要。

## 2. 教育効果・コンテンツの正確性

- **英文の文法的正確性**: テンプレート×語彙の組み合わせで不自然な文・文法誤り（三単現のs、冠詞、時制の一致など）が生成されないか、ネイティブチェック/自動検証が重要。
- **誤答時のフィードバックの薄さ**: `GameScreen.tsx` は不正解時に正解文を出すだけで、`note`（文法解説）は正解時にしか表示しない。誤答時にこそ解説を出す方が学習効果が高い。
- **どこが間違っていたかの可視化なし**: 語順を丸ごと比較するだけで、どのタイルが違ったかのdiff表示がない。
- **スペースドリピティション不在**: 誤答の記録・苦手文型の優先再出題がない（`pickQuestions`は完全ランダム）。復習モードは教育効果が大きい。
- **英検グレードとの整合性**: レベル名が英検4級〜2級を明示しているため、実際の出題範囲・文法項目との齟齬は信頼低下に直結する。

## 3. UI/UX（子ども向け）

- **タップ操作の一貫性**: ドラッグ&ドロップでなくタップ配置/削除方式。スロット同士のスワップができず、1語だけ間違えた時の修正が面倒。
- **読みやすさ**: 高校レベルの長い構文でタイル行が画面幅に収まるか、小画面端末での実機確認が必要。
- **色のみに依存した状態表現**: タイマーバーの色変化（urgent/warn）が視覚のみ。色覚特性への配慮（形状・アイコン併用）を検討。
- **モーション過多への配慮**: シェイク・フラッシュ・コンフェッティ演出が `prefers-reduced-motion` を尊重していない可能性。光感受性への配慮も確認。

## 4. アクセシビリティ

- **スクリーンリーダー対応**: タイル/スロットの `aria-label` が単語内容を適切に伝えているか。
- **キーボード操作**: タップ前提のUIで、キーボードのみでのプレイ（Tab移動→Enterで配置）が可能か。
- **音声のみに頼らない設計**: 日本語プロンプト読み上げはSFXオン時のみ発火。音を出せない環境（学校・図書館）や聴覚障害のある子どもでも、視覚情報だけで完結するか。

## 5. 音声・TTS（Web Speech API依存の弱さ）

- **端末依存の音声品質**: `src/audio/speech.ts` はブラウザ内蔵TTSに依存。音声パック未インストール端末では無音になりうる。フォールバック（テキストのみ）が必要。
- **iOS Safariの制約**: Web Audio APIはユーザー操作なしに音を鳴らせない。`soundEngine.ts` がユーザー操作起点で `AudioContext` を初期化・resumeしているか確認。
- **BGM/SFXのリアルタイム合成負荷**: 低スペック端末でのカクつきの可能性。

## 6. PWA・技術基盤

- **強制横画面のフォールバック**: `src/hooks/useForcedLandscape.ts` はCSS回転＋Screen Orientation API併用（良い設計）。iOS Safariは`orientation.lock`非対応、アプリ内ブラウザ（LINE/Instagram等）での見え方も確認。
- **バックグラウンド時のタイマー**: `setInterval` ベースのタイマーはタブ非アクティブ時にスロットリングされ、復帰時に不公平なゲームオーバーが起きうる。`visibilitychange` でのポーズ対応が望ましい。
- **PWA更新戦略**: `registerType: 'autoUpdate'`。新コンテンツ配信時にプレイ中ユーザーへ更新を促す導線があるか。
- **オフライン完結**: 効果音はWeb Audio合成でオフライン完結。ただしTTSはOS内蔵音声依存のため厳密には非オフライン。
- **セーフエリア対応**: `display: 'fullscreen'` の横画面PWAは、ノッチ/パンチホール端末での `env(safe-area-inset-*)` 対応が必要。

## 7. データ・プライバシー（子ども向けアプリ特有）

- **COPPA/GDPR-K相当の配慮**: `src/utils/storage.ts` は `localStorage` にベストスコアを保存するのみで外部送信なし＝現状は理想的。今後アナリティクスやログイン機能を追加する際は保護者同意フローが必要。
- **端末変更・データ削除で進捗消失**: サーバー同期がなく `localStorage` クリアで進捗全消失。クラウド同期/アカウント機能の要否を検討。

## 8. 品質保証・保守性

- **自動テストの不在**: `questionGen.ts`（手続き生成ロジック）や `resolve()` のスコア計算・星判定など、ロジックが複雑な箇所ほどユニットテストの価値が高い。
- **CI不在**: PRごとの自動lint/typecheck/testの仕組みがあると安全。
- **多端末での実機QA必須**: 横画面固定・フルスクリーン・音声合成など多くのブラウザAPIに依存するため、Android Chrome / iOS Safari / 低スペック端末での実機確認が欠かせない。

## 9. 運用・グロース観点

- **リプレイ性**: 1セッション10問固定で短く区切られているのは良いが、飽き対策（デイリーチャレンジ、実績、ランキング）は現状なし。
- **共有機能なし**: スコアのSNSシェア導線がなく、口コミ拡散の機会を逃している可能性。
- **保護者向け情報**: 「何を学べるか」「進捗確認」を見せる画面がなく、子ども個人のプレイのみで完結している。
