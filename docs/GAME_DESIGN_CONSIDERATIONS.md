# このゲームを作る／育てる上で気にすべきこと

「英単語ならべ」（英単語ならべかえPWA）のような、**子ども向け・語順パズル型・英語学習・PWA** ゲームを開発・改修する際に検討すべき論点のメモ。将来のセッションで参照する目的で残す。実装済みの箇所は該当ファイルを添え、未対応/要検討の箇所は理由とセットで書く。

対応済みの項目には ✅ とPR番号を付けている。このドキュメント自体も見直すたびに更新すること。

## 1. ゲームデザイン・バランス

- **スコアリングの公平性**: `src/components/GameScreen.tsx` の `resolve()` は `timeBonus = timeLeft * 2` を加算しており、正確さより速さが得点を左右する。じっくり考える子が不利にならないか。
- ✅ (#8) **ライフ制のプレッシャー**: 残機切れで即終了する問題は、タイマー・ライフなしの「練習モード」（設定モーダルの🧪練習モード）を追加して緩和した。ベストスコアには反映しない。残機は現在 `START_LIVES = 10`。
- ✅調査済み（対応不要）**出題プールの枯渇**: 実測値は eiken4: 341, eiken3: 239, eikenPre2: 248, eiken2: 210, koukoNyushi: 562（計1,600問）。1セッション10問なので、素朴に繰り返し遊んでも暗記ゲー化するほど早くは枯渇しない。加えて (#11) の復習出題も全体からすれば少数を優先的に混ぜるだけなので、プール自体の拡張は現時点では不要と判断。
  - ⚠️ ただし (#28) の「ずっと続ける」で前提が変わった。補充時の重複排除はキューに残っている問題に対してのみで、**すでに出題済みのIDは保持していない**ため、1回の run が210問を超えると（英検2級が最短）重複が出始める。子どもの1回のプレイでそこまで到達する可能性は低いと判断して未対応。
- ✅ (#28) **プレイ時間の選択肢**: タイトルの開始ボタンを「10問チャレンジ」（従来の固定10問）と「ずっと続ける」（ライフ切れ、またはHUDの「やめる」まで出題しつづける）の2つに分けた。エンドレスは30問ずつ先読みでキューを補充する（`ENDLESS_BATCH` / `ENDLESS_REFILL_AT`）。
- ✅ (#30) **ベストスコアがモード間で不公平**: ベストスコアと★はレベル単位で両モード共通の1レコードのまま。ただし比較を生スコアから `normalizedScore()`（1問あたりに割ってから10問分に戻した「10問換算スコア」）に変えた（`src/utils/scoring.ts`）。10問チャレンジの換算スコアはその run のスコアそのものなので、既存の記録も表示・順位づけとも変わらない。長く走っただけのエンドレスは勝てなくなる。★は従来どおり `MIN_RANKED_QUESTIONS`（10問）未満を0にして、1問だけ解いて やめる で★3を取る抜け道を塞いである。レベル選択カードは換算値を表示し、記録の出所がエンドレスの場合のみ「∞ N問を10問換算」を添える。結果画面もエンドレスのときだけ換算値を出す（生スコアが大きいのに記録更新されない理由が分かるように）。
- ✅ (#30) **成長記録の計上漏れ**: 旧実装は `recordMissedOnly()` を `resolve()` の中で `isLastQuestion || outOfLives` のときだけ呼んでいた。そのため **一発勝負モードで最終問題以外を間違えると、その問題は成長記録にまったく計上されない**（ライフ切れ経路と、ずっと続ける で やめる を押した場合も同様）という取りこぼしがあった。集計方法を変更し、`GameScreen` がセッション中の各問題の最新状態を `questionOutcome: Map<string, 'missed' | 'recovered'>` で持ち、セッション終了時に `'missed'` のまま残っているものを数えて `recordMissedOnly(count)` を1回だけ呼ぶようにした。エンドレスで一度克服した問題が再出題されて再び間違えるケースも正しく扱える。これで `firstTry + recovered + missedOnly === totalAnswered` が常に成立する。
- **難易度カーブ**: レベル内の出題順が完全ランダムなため、難しい構文が1問目に来ることがある。段階的難易度にするかは意図次第。
- **タイムリミットの根拠**: `src/data/levels.ts` でレベルが上がるほど制限時間が短くなる（26秒→19秒）一方、文は長く複雑になる。対象年齢での実プレイテストが必要。

## 2. 教育効果・コンテンツの正確性

- **英文の文法的正確性**: テンプレート×語彙の組み合わせで不自然な文・文法誤り（三単現のs、冠詞、時制の一致など）が生成されないか、ネイティブチェック/自動検証が重要。
  - ✅ `src/data/grammarValidation.ts` + `grammarValidation.test.ts` を追加し、全レベルの問題バンクに対して構造面のサニティチェック（先頭大文字・終端句読点・二重スペース/連続同一単語・`${...}`のようなテンプレート展開漏れ）をCIで自動検証するようにした。ただし三単現のsや冠詞・時制の一致のような意味的な文法正しさまでは検証できておらず、そこはネイティブレビューに頼る必要が引き続きある。
- ✅ (#4) **誤答時のフィードバックの薄さ**: 不正解時にも `question.note`（文法解説）を表示するようにした（従来は正解時のみ）。
- ✅ (#6) **どこが間違っていたかの可視化なし**: 誤答時、`question.words[i]` と一致しないスロットに赤枠のミスマッチ表示を追加した（`WordTile.tsx` の `AnswerSlot` `mismatch` prop）。
- ✅ (#11) **スペースドリピティション不在**: `src/utils/reviewQueue.ts` を追加し、レベル単位で誤答した問題id（最大30件）を`localStorage`に記録。`pickQuestions()` の `priorityIds` 引数でセッションに優先的に含めるようにした（専用UIは追加せず、出題の裏側だけを調整するシンプルな方式を選択）。正解すると記録から外れる。
  - ✅ 単なる「誤答リスト」から軽量SM-2方式の間隔反復に強化。誤答した問題は次回すぐ出題対象になり（`step:0`）、復習で正解するたびに 1日→3日→7日→14日 と出題間隔が広がり、最後まで抜けると（マスター済みとして）キューから外れる。誤りをまた重ねると `step:0` に戻る。`loadDueIds()`/`recordCorrect()`/`recordMiss()`（旧 `loadMissedIds`/`recordMastered`）で日時ベースの `dueAt` を管理。旧フォーマット（文字列配列のみ）のデータも移行して読み込む。
- **英検グレードとの整合性**: レベル名が英検4級〜2級を明示しているため、実際の出題範囲・文法項目との齟齬は信頼低下に直結する。

## 3. UI/UX（子ども向け）

- **タップ操作の一貫性**: ドラッグ&ドロップでなくタップ配置/削除方式。スロット同士のスワップができず、1語だけ間違えた時の修正が面倒。（UXの根本的な変更になるため、キッズ向けの分かりやすさを損なわないか要検証してから着手する）
  - ✅ 根本原因は「スロットが全部埋まった瞬間に即採点される」ことだった（間違いに気づいた時にはもう不正解が確定していた）。`GameScreen.tsx` に `CONFIRM_GRACE_MS`（650ms）の確認猶予を追加し、最後のタイルを置いても即座には採点せず、その間にどれかの解答欄をタップすればタイルをトレイに戻して直せるようにした（採点はキャンセルされる）。直さなければ猶予後に自動で採点される（すぐ確信が持てる子のテンポは大きく変えない）。スロット同士を直接入れ替える専用ジェスチャーはまだ無く、直すには一度トレイに戻して置き直す必要がある。
- ✅ (#30) **確認猶予中もタイマーが動いていた**: 一発勝負モードで全スロットを埋めた後の `CONFIRM_GRACE_MS`（650ms）は「置き間違いに気づくための時間」であって「解くための時間」ではないのに、その間もカウントダウンが進み、正解しているのに時間切れとして採点され得た。タイマーの `useEffect` の停止条件に `awaitingConfirm` を追加した。
- ✅ (#17) **タイル一覧の位置ズレ**: タップして単語を置くたびに、`tray` 配列から要素を削除していたため残りのタイルが再センタリングされて位置がズレ、連続タップしづらかった。`tray` はレベル/問題が変わるまで並び順を固定したままにし、配置済みのタイルは配列から消す代わりに `opacity: 0; pointer-events: none;`（`WordTile.tsx` の `placed` prop）で見た目だけ消してレイアウト上の場所を保持するようにした。Playwrightで、中間のタイルをタップしても他のタイルの座標が変わらないことを確認済み。
- **読みやすさ**: 高校レベルの長い構文でタイル行が画面幅に収まるか、小画面端末での実機確認が必要。
- **色のみに依存した状態表現**: タイマーバーの色変化（urgent/warn）が視覚のみ。色覚特性への配慮（形状・アイコン併用）を検討。
- ✅ (#4, #5, #30) **モーション過多への配慮**: `prefers-reduced-motion` 時に、シェイク・フラッシュ・コンフェッティ・タイマー緊急パルス・コンボ炎アイコン・確認ボタン (#4, #5) に加えて、残っていた無限ループ4つも止めるようにした (#30): タイトルの10問チャレンジボタンの脈動とロゴタイルの浮遊（`TitleScreen.module.css`）、レベルカードのアイコン浮遊（`LevelSelect.module.css`）、結果画面のNew Bestの脈動（`ResultScreen.module.css`）。一度きりで静止する `pop-in` の登場アニメーションは意味を持つので残してある。
  - 副作用として、Playwrightが脈動中のボタンを「静止しない要素」と見なしてクリックできない問題があった。reduced-motionをエミュレートしないテストでは依然クリックできないので、タイトル画面を操作するテストは `eval` でクリックする必要がある。

## 4. アクセシビリティ

- ✅ (#13) **スクリーンリーダー対応**: タイル/スロットはネイティブ `<button>` なのでキーボード操作・読み上げの基本は元から効いていたが、`aria-label` を追加してより分かりやすくした（単語タイルは「{word} を置く」、解答欄は「解答欄 N：{word}。タップで取り消し」、空欄は「解答欄 N：空」）。タイル列・解答欄にも `role="group"` + `aria-label` を付けてグループとして認識できるようにした。
- **キーボード操作**: `<button>` ベースなのでTab移動＋Enter/Spaceでの操作は元から可能。
- **音声のみに頼らない設計**: 日本語プロンプト読み上げはSFXオン時のみ発火。音を出せない環境（学校・図書館）や聴覚障害のある子どもでも、視覚情報だけで完結するか（現状、単語タイル自体は常にテキスト表示なので大きな問題はなさそう）。

## 5. 音声・TTS（Web Speech API依存の弱さ）

- ✅ **正解時のみの読み上げ**: 従来 `speakEnglish()` は正解した時にしか発火せず、間違えた問題の正しい発音を聞く機会がなかった。`GameScreen.tsx` の `resolve()` で不正解時にも読み上げるようにし、「正解: ...」のテキスト表示と合わせて音でも正しい語順・発音を復習できるようにした。
- **端末依存の音声品質**: `src/audio/speech.ts` はブラウザ内蔵TTSに依存。`isSpeechSupported()` で非対応環境は静かにno-opになる設計は既にできている（テキスト表示は常にあるのでフォールバックとして十分）。
- ✅ (#29) **発話完了イベントの取りこぼしでゲームが止まる**: `speak()` が返す Promise は `onend`/`onerror` でしか解決せず、しかもこの Promise がゲーム進行を握っていた（日本語プロンプト読み上げ完了まで**タイマーが始まらない**／英語読み上げ完了まで**次の問題に進まない**）。Chromeは発話中のバックグラウンド化などで `end` イベントを落とすことがあり、その場合リロード以外に復帰手段のないフリーズになっていた。`SPEECH_TIMEOUT_MS`（10秒）のタイムアウトを追加し、時間切れなら `synth.cancel()` してから解決するようにした。二重解決しないこと・正常終了時にタイマーを片付けることも含めて `speech.test.ts` でカバー。
- **iOS Safariの制約**: `soundEngine.ts` の `unlock()` はユーザー操作（`onPointerDown`）から呼ばれており（`App.tsx`）、対応済み。
- **SFXのリアルタイム合成負荷**: 低スペック端末でのカクつきの可能性は未検証。

## 6. PWA・技術基盤

- **強制横画面のフォールバック**: `src/hooks/useForcedLandscape.ts` はCSS回転＋Screen Orientation API併用（良い設計）。iOS Safariは`orientation.lock`非対応、アプリ内ブラウザ（LINE/Instagram等）での見え方も確認。
- ✅ (#4, #5) **バックグラウンド時のタイマー**: `visibilitychange` を監視し、タブ非表示中はカウントダウン（インターバル）と正解後の自動遷移（`setTimeout`）の両方を一時停止するようにした。
- **PWA更新戦略**: `registerType: 'autoUpdate'`。新コンテンツ配信時にプレイ中ユーザーへ更新を促す導線があるか。
- **オフライン完結**: 効果音はWeb Audio合成でオフライン完結。ただしTTSはOS内蔵音声依存のため厳密には非オフライン。
- ✅ (#15) **セーフエリア対応**: `src/styles/global.css` の `.app-canvas` に、向き別に物理→視覚エッジを変換する `--safe-top/right/bottom/left` カスタムプロパティを追加。`is-landscape` は1:1、`is-portrait`（CSS回転中）は `rotate(90deg)` の回転方向を数式で導出し、物理top→視覚left、物理right→視覚top、物理bottom→視覚right、物理left→視覚bottomの対応で `env(safe-area-inset-*)` を割り当てた。各画面の `.screen` に `padding: var(--safe-top) var(--safe-right) var(--safe-bottom) var(--safe-left)` を適用（ノッチなし端末では全て0pxなので既存レイアウトに影響なし）。iPhone実機で確認済み — 方向は正しかった。

## 7. データ・プライバシー（子ども向けアプリ特有）

- **COPPA/GDPR-K相当の配慮**: `src/utils/storage.ts` は `localStorage` にベストスコアを保存するのみで外部送信なし＝現状は理想的。今後アナリティクスやログイン機能を追加する際は保護者同意フローが必要。
- **端末変更・データ削除で進捗消失**: サーバー同期がなく `localStorage` クリアで進捗全消失。クラウド同期/アカウント機能の要否を検討。

## 8. 品質保証・保守性

- ✅ (#7) **自動テストの不在**: Vitest導入済み（`npm test`）。`questionGen.ts`（`q()`）、`questions.ts`（`pickQuestions()`、全レベルの問題バンクのデータ整合性）、`storage.ts`（ベストスコアの保存/取得ロジック）をカバー。
- ✅ (#9) **CI不在**: `.github/workflows/ci.yml` を追加し、push/PRごとに `npm ci` → `lint` → `test` → `build` を自動実行するようにした。なお `oxlint` は警告があっても exit 0 なので、警告だけではCIは落ちない。
- ✅ (#30) **lint警告の常態化**: 8件の警告が出っぱなしで、新しい警告が埋もれる状態だったので0件にした。
  - `react(purity)`（`Confetti.tsx`、6件）: レンダー中に `Math.random()` を呼んでいた。`useState` の遅延初期化に移し、マウント時に1回だけ抽選するようにした。コンポーネントは問題ごとに `key` で作り直されるので、新しい紙吹雪が要るときは再マウントされる。
  - `react(only-export-components)`（3件）: コンポーネントと非コンポーネントを同じモジュールから export していると React Fast Refresh が効かない。`estimateTileWidth` を `components/tileWidth.ts` に、コンテキスト本体とフックを `context/sound.ts` / `context/settings.ts` に分離し、`SoundContext.tsx` / `SettingsContext.tsx` はプロバイダだけを export するようにした。ファイル名の大文字小文字だけが違う名前（`soundContext.ts`）は、Windows/macOSの大文字小文字を区別しないファイルシステムで `SoundContext.tsx` に解決されてしまうため避けている。
- ❌調査済み（対応しない）**バンドルに全1,600問が同梱**: `dist/assets/index-*.js` は334kB（gzip 105kB）で、その大半が問題バンク。レベル別に動的importすれば初回パースは軽くなるが、**このアプリでは意味がない**。`vite.config.ts` のworkbox設定が `globPatterns: ['**/*.{js,css,html,png,svg,ico,woff2}']` で全JSチャンクをプリキャッシュするため、分割してもService Worker導入時に結局すべてダウンロードされる。プリキャッシュ対象から外せば初回は軽くなるが、未訪問のレベルがオフラインで遊べなくなる。オフラインで完結することの方がこのアプリには重要なので、現状維持とする。
- **多端末での実機QA必須**: 横画面固定・フルスクリーン・音声合成など多くのブラウザAPIに依存するため、Android Chrome / iOS Safari / 低スペック端末での実機確認が欠かせない（CIではカバーできない領域）。

## 9. 運用・グロース観点

- **リプレイ性**: 現在は「成長記録」（`src/components/ProgressScreen.tsx` + `src/utils/progressStats.ts`）が唯一の継続動機。累計解答数と、最初から正解／間違えてから正解／正解できなかった の内訳を全レベル横断で見せる。
  - ❌ **実績（バッジ）システムは削除した (#29)**: かつて `src/utils/achievements.ts` + `AchievementsScreen.tsx` で5種類のバッジを実装していたが、タイトル画面を成長記録に一本化した際に一覧画面への導線が失われ、「クリア直後にバナーが1度出るだけで二度と確認できない」書き込み専用の状態になっていた。成長記録があれば継続動機としては足りると判断し、コードごと削除。復活させるなら成長記録画面への統合を前提にすること。
  - ❌ **デイリーチャレンジも削除した (#29)**: `src/utils/dailyChallenge.ts`（日付シードの決定的PRNGで全プレイヤー共通の10問を出す）は、タイトル画面から📅ボタンが外された時点でどこからも呼ばれない死にコードになっていた。テストだけが唯一の利用者だったため削除。ロジック自体は使えるので、復活させるなら git 履歴から戻せる。
  - ランキング（他プレイヤーとの比較）は未着手。
- **共有機能なし**: スコアのSNSシェア導線がなく、口コミ拡散の機会を逃している可能性。
- **保護者向け情報**: 「何を学べるか」「進捗確認」を見せる画面がなく、子ども個人のプレイのみで完結している。

## 次にやるとよさそうな候補（優先度順の目安）

1. スコアリングの公平性（`timeBonus = timeLeft * 2` による速さ偏重の見直し）や難易度カーブの調整
2. 文法検証の強化（三単現のs・冠詞・時制の一致のような意味的な正しさのチェック）
3. エンドレスで既出IDを保持し、1回のrunが210問を超えても重複しないようにする
4. スロット同士を直接入れ替える専用ジェスチャー（現状は一度トレイに戻して置き直す必要がある）
5. リプレイ性の再強化（ランキング・SNS共有など。実績とデイリーチャレンジは削除済みなので、戻すなら成長記録への統合を前提に）
6. 色のみに依存した状態表現（タイマーバーのurgent/warn）への形状・アイコン併用
7. PWA更新戦略（`registerType: 'autoUpdate'`。プレイ中の更新をどう扱うか）
